# 📆 Month 4: Integration + Observability - Detailed Plan

## 🎯 Month 4 Goals
- Connect everything you've built (Gateway, Auth, Notification, Task services) into one working system
- Add logging and basic metrics so you can "see" what your system is doing
- Write real tests instead of just manual Postman checks

## Week 2: Structured Logging

### Day 8 - Why Structured Logging
- [ ] Understand the difference between `console.log` and structured logs (JSON logs with timestamp, level, service name)
- [ ] Learn why this matters at scale (searchable, filterable logs)

### Day 9 - Install a Logging Library
- [ ] Install `winston` (or similar) in one service
- [ ] Set up basic log levels: info, warn, error

### Day 10 - Add Logging to Gateway
- [ ] Log every incoming request and its response status/time
- [ ] Log any errors that occur

### Day 11 - Add Logging to Auth Service
- [ ] Log signup attempts, login successes/failures (never log the actual password)

### Day 12 - Add Logging to Task Service
- [ ] Log when a task is submitted, started, completed, or failed

### Day 13 - Centralize Log Format
- [ ] Make sure all services use the same log format/structure
- [ ] Add a `service` field so you know which service produced each log line

### Day 14 - Revision
- [ ] Run the full system and watch logs across all services during a test flow
- [ ] Push to GitHub

---

## Week 3: Basic Metrics + Monitoring

### Day 15 - What Are Metrics
- [ ] Learn the difference between logs (events) and metrics (numbers over time — request count, latency, error rate)

### Day 16 - Simple Metrics Endpoint
- [ ] Add a `/metrics` route to your Gateway that returns basic counters (total requests, error count)

### Day 17 - Track Request Count
- [ ] Add middleware that increments a counter on every request
- [ ] Expose this via the metrics endpoint

### Day 18 - Track Response Times
- [ ] Measure how long each request takes
- [ ] Track average response time, expose via metrics endpoint

### Day 19 - Track Errors
- [ ] Count how many requests result in errors (4xx/5xx)
- [ ] Expose error count/rate via metrics endpoint

### Day 20 - Health Check Endpoints
- [ ] Add a `/health` endpoint to each service (just returns "OK" if the service is alive)
- [ ] This is a real production pattern — Docker/Kubernetes/load balancers use this

### Day 21 - Revision
- [ ] Check `/metrics` and `/health` work across all services
- [ ] Push to GitHub
