## Week 1: Redis Basics

### Day 1 - What is Redis
- [ ] Learn Redis is an in-memory data store (very fast, temporary by default)
- [ ] Understand common use cases: caching, sessions, queues

### Day 2 - Install & Connect
- [ ] Install Redis locally (or run via Docker: `docker run redis`)
- [ ] Install `ioredis` in your Node project, connect to Redis

### Day 3 - Basic Commands
- [ ] Learn `SET`, `GET`, `DEL`, `EXPIRE` commands
- [ ] Practice each from Node using `ioredis`

### Day 4 - Caching Pattern
- [ ] Pick a slow-ish operation (e.g. fetching notifications list)
- [ ] Cache its result in Redis, read from cache first, fall back to real fetch if not cached

### Day 5 - Cache Invalidation
- [ ] Learn when/why to expire or clear cached data
- [ ] Add expiry (`EXPIRE`) to your cached keys

### Day 6 - Redis Data Structures (Overview)
- [ ] Get a conceptual overview: strings, lists, hashes, sets
- [ ] No need to master all — just know they exist and when each is used

### Day 7 - Revision
- [ ] Build a small caching demo using your Month 2 Notification service
- [ ] Push to GitHub

## Week 2: Message Queues + BullMQ Setup

### Day 8 - Why Message Queues
- [ ] Understand the problem: slow tasks (emails, reports) shouldn't block the user's request
- [ ] Learn the queue pattern: add job → worker picks it up → processes in background

### Day 9 - Install BullMQ
- [ ] Install `bullmq` and `ioredis`
- [ ] Understand the Queue vs Worker distinction

### Day 10 - Your First Queue
- [ ] Create a queue (e.g. `taskQueue`)
- [ ] Add a simple job to it (simulate "send welcome email")

### Day 11 - Your First Worker
- [ ] Create a worker that listens to `taskQueue` and processes jobs
- [ ] Log when a job starts and finishes

### Day 12 - Retries & Failures
- [ ] Learn how BullMQ retries failed jobs
- [ ] Intentionally make a job fail, observe retry behavior

### Day 13 - Priorities & Delays
- [ ] Learn job priorities (some jobs matter more) and delayed jobs (run later, not now)
- [ ] Try adding a delayed job

### Day 14 - Revision
- [ ] Test full flow: add job → worker processes → check logs
- [ ] Push to GitHub

## Week 3: Build the Task Processing Service

### Day 15 - Plan the Service
- [ ] Decide what real tasks this handles for your FYP (e.g. report generation, batch notifications)

### Day 16 - Structure as Standalone Service
- [ ] Create `task-service` as its own Express app with a BullMQ worker inside

### Day 17 - Submit Task Endpoint
- [ ] Build `POST /tasks` — adds a job to the queue, returns a task ID immediately

### Day 18 - Worker Processing Logic
- [ ] Build the actual processing logic (can be simulated — wait a few seconds, then mark done)

- [ ] Build `GET /tasks/:id` — returns pending/completed/failed status

### Day 20 - Store Task Results
